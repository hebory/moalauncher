# 구성 및 동작

Moa Launcher는 .NET 8 WPF 앱과 .NET 8 코어 라이브러리로 나눕니다. UI는 화면 입력, 진행 상태 및 오류를 표시하고 `MoaLauncher.Core`의 서비스 인터페이스를 호출합니다. 코어에는 공개 카탈로그 모델, 설치 모델, 릴리스 선택 규칙, 파일 경로 검사, GitHub API 캐시와 패키지 다운로드가 있습니다.

## 요청 흐름

앱에 포함된 `catalog/apps.json`이 배포 기본값입니다. 런타임은 `%LOCALAPPDATA%\MoaLauncher\catalog.json`의 사용자 카탈로그를 합칩니다. UI 편집과 가져오기 기능은 사용자 카탈로그에 원자적으로 저장합니다. `CatalogService`는 JSON 스키마 버전, 중복 ID, GitHub 저장소 이름, 프로세서별 설치 파일 패턴, 파일 경로를 검증합니다.

`moa-launcher`는 코드에 정의한 내장 항목입니다. 사용자 카탈로그의 동명 항목은 무시하며 앱 편집과 가져오기에서 변경할 수 없습니다. 화면 버전은 현재 런처 어셈블리에서 읽습니다.

`GitHubReleaseService`는 공개 REST API의 최신 안정 릴리스를 읽고 ETag 및 JSON 응답을 캐시합니다. GitHub가 네트워크 오류를 반환하면 기존 조회 결과를 상태 표시용으로만 반환합니다. API에서 다시 읽은 정보와 체크섬을 확인하기 전에는 다운로드하지 않습니다. 순차 조회로 익명 API 요청 한도에 대응합니다.

`ReleaseRules`는 현재 Windows 프로세서에 맞는 카탈로그 항목을 찾아 정확히 하나의 릴리스 자산을 선택합니다. `VerifiedDownloader`는 HTTPS GitHub Release 호스트만 허용하고 크기 제한, 취소, SHA-256 계산을 수행합니다. `InstallationService`는 직접 GitHub URL, 패키지 종류, 체크섬을 다시 검사합니다.

## Windows 자동 실행과 트레이

Windows 시작 시 자동 실행은 기본으로 꺼져 있습니다. 사용자가 설정에서 켜면 현재 사용자 레지스트리의 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`에 `MoaLauncher` 값으로 실행 파일 경로, `--background`, `--data-dir`와 현재 데이터 폴더를 등록합니다. 경로의 공백·한글·끝 역슬래시를 인용하고 Windows Run의 260자 명령 길이 제한을 넘으면 등록 전에 오류를 표시합니다. 로그인 시 창을 표시하지 않고 트레이 아이콘과 설정·카탈로그·타이머를 초기화합니다. 시작 시 업데이트 확인과 주기 확인은 기존 설정을 따르며 자동으로 설치하지 않습니다. 설정 화면에 표시되는 자동 실행 상태는 현재 실행 파일과 데이터 폴더에 일치하는 Run 등록에서 직접 읽으며 `settings.json`에 중복 저장하지 않습니다. 등록·해제 실패 시 실제 등록 상태로 토글을 복원합니다.

런처를 직접 다시 실행하면 이미 실행 중인 인스턴스의 창을 복원합니다. `--background`로 중복 실행한 경우에는 창을 복원하지 않고 두 번째 프로세스만 종료합니다. 자동 실행 등록은 현재 실행 파일의 경로를 가리키므로 포터블 폴더를 옮기면 기존 등록이 낡은 경로를 가리킬 수 있습니다. 새 위치의 설정 화면에서는 일치하지 않는 등록이 꺼짐으로 표시되며, 다시 켜면 새 경로로 교체합니다. 창을 닫으면 트레이에 남으며 아이콘에서 창을 열거나 명시적으로 종료할 수 있습니다.

## 업데이트 알림

`LauncherSettings.UpdateNotifications`는 기본 `true`이며, 기존 `settings.json`에서 항목이 빠져 있어도 켜짐으로 읽습니다. 설정에서 변경한 값은 다른 확인 설정과 함께 원자적으로 저장합니다. 알림을 꺼도 릴리스 조회·주기 타이머·목록 갱신은 계속하고 공통 알림 호출만 생략합니다. 꺼진 동안 발견한 버전은 알림 기록에 추가하지 않으므로 다시 켠 뒤 다음 확인에서 알릴 수 있습니다. 이미 알린 버전의 중복 억제 기록은 설정을 껐다 켜도 유지합니다.

시작·주기·수동 릴리스 확인이 끝나면 설치되어 있고 실제 새 버전이 확인된 앱을 트레이 알림으로 묶어 표시합니다. 새 버전 여부가 캐시만으로 확인된 경우, 조회 오류가 난 경우, 아직 설치되지 않은 앱은 알리지 않습니다. 한 실행 세션에서 `(앱 ID, GitHub 저장소, 릴리스 태그)` 조합은 한 번만 알립니다. 앱 ID별 알림 기록은 클릭 후 상태가 변했거나 알림을 늦게 눌러도 현재 카탈로그와 대조할 수 있도록 세션 동안 유지합니다. 런처를 재실행하면 중복 억제 기록이 초기화되어 같은 버전을 다시 알릴 수 있습니다.

일반 프로그램의 트레이 업데이트 알림을 누르면 메인 창을 복원하고 설정 화면을 닫아 업데이트 목록으로 이동합니다. 검색을 비우고, 알림 대상 중 여전히 업데이트할 수 있는 앱을 목록 위에 표시합니다. 그 사이 앱을 업데이트하거나 제거해 알림 대상이 더 이상 없으면 현재 상태를 기준으로 업데이트 목록을 표시합니다. 알림은 탐색을 돕는 안내일 뿐 설치를 실행하지 않습니다. 사용자가 앱의 업데이트 버튼을 눌렀을 때 런처가 GitHub 최신 릴리스와 SHA-256을 다시 확인하고 기존 설치 흐름을 사용합니다. 알림 배너의 표시는 Windows 알림 설정과 집중 모드 등 OS 정책의 영향을 받습니다.

## 런처 자체 업데이트

내장 Moa Launcher 상태는 내부적으로 유지하지만 일반·설치됨·업데이트 목록과 프로그램 개수에서는 제외합니다. **설정 → 런처 정보 및 업데이트**에서 현재 버전과 공개 `hebory/moalauncher` 저장소의 최신 안정 릴리스(`MoaLauncher-*-Setup-x64.exe`)를 확인합니다. 업데이트 확인 간격과 트레이 알림 켜기/끄기는 다른 앱과 공유하며, 설정의 확인 버튼으로 런처만 별도 조회할 수도 있습니다. 알림 클릭 시 현재도 업데이트 가능한 일반 앱 대상이 있으면 프로그램 목록으로 이동하고, 런처 대상만 남았으면 설정 상단으로 이동합니다. 늦게 누른 런처 알림도 설정에서 현재 상태를 보여 줍니다. 새 버전은 설정 버튼에 표시하고, 사용자가 **업데이트 후 재시작**을 선택할 수 있습니다. 앱 설치나 다운로드 작업이 진행 중이면 자체 업데이트 시작을 거부합니다. 자체 업데이트 경로는 일반 앱의 설치 상태나 사용자 카탈로그를 수정하지 않습니다.

런처는 API에서 최신 릴리스와 자산 체크섬을 다시 확인한 다음 설치 프로그램을 `%LOCALAPPDATA%\MoaLauncher\self-update\<작업 ID>`에 내려받습니다. 기존 설치 대상은 설치 전 실행 중인지 확인하고, 다운로드된 설치 파일의 SHA-256을 검증합니다. 이어 현재 게시 디렉터리의 전체 파일을 같은 작업의 `runner` 폴더에 복사하고 복사본을 helper 모드로 실행합니다. helper의 준비 응답을 받은 뒤 UI 프로세스가 종료되면 helper가 Inno Setup을 조용히 실행하고 설치된 실행 파일 버전을 확인합니다. 완료 후 동일한 설치 대상과 데이터 폴더로 재시작하고, 원래 백그라운드 상태였다면 창 없이 트레이에서 시작합니다. 자동 실행 레지스트리 등록은 설치 과정에서 바꾸지 않으므로 기존 경로를 유지합니다.

설치가 실패하거나 설치 후 버전 확인에 실패하면 helper는 기존 실행 파일 백업을 복구하고 런처를 다시 시작하려 시도합니다. 백업과 설치 로그는 `self-update/<작업 ID>` 폴더에 보존하며, 데이터 폴더의 `self-update-result.json`에 결과를 기록합니다. 런처가 읽은 결과는 `.json.last` 파일로 보존합니다. 복구 실패 시 백업 위치와 오류를 기록하고 자동 재시작하지 않습니다. Inno Setup 설치기의 Windows 등록 메타데이터까지 완전히 이전 상태로 되돌린다고 보장하지는 않습니다. 이 작업 폴더는 자동 정리하지 않습니다.

## 설치 위치와 복구 동작

기본 포터블 ZIP은 `%LOCALAPPDATA%\MoaLauncher\apps\<앱 ID>\<버전>`의 임시 버전 폴더에서 다운로드 검증과 안전한 압축 해제를 마친 뒤 상태 파일을 갱신합니다. 압축 엔트리 개수, 전체 크기, 각 항목의 크기, 압축 비율과 경로를 제한합니다. 압축 해제 중 취소나 오류가 나면 새 임시 폴더를 정리하고 현재 버전 폴더를 건드리지 않습니다. 이전 버전 폴더는 보존하지만, 런처 화면에서 버전을 선택해 되돌리는 기능은 아직 없습니다.

Inno Setup 파일은 앱의 배포자가 제공한 설치 프로그램을 `%LOCALAPPDATA%\Programs\MoaView`와 같은 사용자 지정 폴더로 실행합니다. 설치 전에 대상 실행 파일 프로세스를 검사해 실행 중 교체를 멈춥니다. 설치 프로세스의 반환 코드와 설치 결과 버전을 확인한 뒤에 런처 설치 상태를 저장합니다. 설치 프로그램이 직접 파일을 변경한 뒤 실패하면 런처가 이를 되돌릴 수 없습니다. 앱을 설치한 뒤 해당 프로그램의 라이선스, 인증, 시작 안내가 나타날 수 있습니다.

## 상태와 사용자 파일

런처는 `%LOCALAPPDATA%\MoaLauncher`에 앱 설정, 설치 메타데이터, 다운로드와 캐시, `launcher.log`를 저장합니다. 앱의 실제 설정과 사용자 데이터는 각 프로그램이 따르는 기본 위치에 남습니다. ZIP 설치 버전을 바꾸거나 추가하더라도 이 데이터 폴더에 앱을 삭제하거나 실행 파일을 찾아 사용자 데이터를 정리하는 기능은 제공하지 않습니다.

`MoaLauncher.App`은 `IReleaseService`와 `IInstallationService`에 의존하므로 테스트에서 네트워크, 디스크와 설치 프로그램 실행을 대체할 수 있습니다. 코어 테스트는 저장소 형식, 버전 정렬, 선택 규칙, HTTP 오류, 체크섬과 ZIP 경로 검사를 다룹니다.

## 의도된 첫 출시 경계

첫 출시는 Windows x64 WPF와 공개 GitHub의 최신 안정 릴리스에 초점을 맞춥니다. 릴리스 캐시는 한도에 도달할 수 있으므로 사용자 로그인이나 GitHub 토큰이 필요한 API 연동은 사용하지 않습니다. 트레이 상주, 선택 가능한 로그인 시 자동 실행, 업데이트 배너 알림과 사용자가 시작하는 Moa Launcher 자체 업데이트를 지원합니다. 다른 프로그램의 업데이트는 사용자가 앱별 업데이트를 시작하며, 일반 앱 업데이트의 설치 실패를 런처가 롤백하지는 않습니다. 자체 업데이트는 런처 실행 파일 복구를 시도하지만 설치기의 Windows 등록 메타데이터 롤백까지 보장하지 않습니다.
